# Fixed asset acquisition browser evidence

Run `npm run test:fixed-asset-acquisition-browser:e2e` from `server` after installing the root and server dependencies. Set `POSTGRES_IMAGE` to the required PostgreSQL version, `REFS_ASSET_ACQUISITION_BROWSER_OUTPUT` to a fresh absolute evidence directory, and `REFS_PLAYWRIGHT_MODULE` when Playwright is installed outside the repository.

The runner refuses an existing evidence directory or a dirty worktree. It launches a fresh owned PostgreSQL container, uses the real accounting API handler and HTTP, and drives isolated Chromium through asset list, detail, acquisition options, one Draft POST, and a fresh Journal read. The browser begins in another open period; the handoff must read the Draft from the source period returned by acquisition options. A browser refresh must resume that exact pending Journal without another POST. Independent Submit, Review, Approve, and Post roles then complete the Journal and reconcile its two ledger lines to the Trial Balance and retained source.

After posting, the browser changes to an exact read-only database identity and refreshes. The asset must show its posted cost and two movements. The real source read must ignore a delayed response after the selected period changes, close an already-open source drill on another period change, and traverse the retained source through Journal and General Ledger to the Trial Balance. The receipt verifier locks the maker and reader permissions, HTTP identities, source ID, GL and Trial Balance amounts and source arrays, posted asset balance, workflow denials, posting count, checks, and screenshot hashes.

Both browser identities are test-only bearers mapped to real database grants and contexts. This evidence does not prove production OIDC, deployed routing, or business acceptance. With the browser flag off, the same PostgreSQL test still executes the real accounting HTTP Draft and independent role/GL/report chain; it is not a silent pass in the ordinary database matrix.

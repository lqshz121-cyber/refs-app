## 第一步：实体与主数据建立

### 1.1 创建实体
**执行者**: 系统管理员
**操作**: `POST /entities`（或通过 UI 实体管理）

**预期结果**:
- 实体创建成功，返回 `entity_id`
- `entity.active = true`
- `audit_event` 中有 `ENTITY_CREATED` 记录

**禁止操作**: 不得使用生产实体 ID；不得使用真实公司名/税号作为测试数据

**证据**: 记录返回的 `entity_id`（UUID），截图

**签核位**: _________________ 日期: _________

### 1.2 建立科目表（COA）
**执行者**: 财务主管
**操作**: 创建以下最小科目集
```

310000 应付账款
```

**签核位**: _________________ 日期: _________

### 2.2 创建手工凭证 DRAFT
**执行者**: 制单人
**操作**: 
```json
{
  "journalNumber": "UAT-JE-001",
  "journalDate": "2026-09-15",
  "currency": "USD",
  "description": "UAT 验收测试凭证",
  "attachmentIds": ["<已上传的附件 UUID>"],
  "lines": [
    {"line_no": 1, "account_code": "610000", "debit_amount": "1000.0000", "credit_amount": "0.0000"},
    {"line_no": 2, "account_code": "111000", "debit_amount": "0.0000", "credit_amount": "1000.0000", "member_ref": "ICBC-001"}
  ]
}
```

**预期结果**:
- 返回 `status: "DRAFT"`, `revision: 0`, `journal_entry_id`

- 凭证不在 `ledger_line` 中（未过账）

**禁止操作**: 
- 不得使用借贷不平的数值
- 不得使用无效期间

**证据**: API 响应截图（含 journal_entry_id）

## 第四步：期间关账

**前提**: 所有预期凭证已过账；无 PENDING outbox；银行对账已完成

**执行者**: 财务主管（需 `GL.PERIOD.CLOSE` 权限）
**操作**: `POST /entities/{id}/periods/{periodId}/close`

**预期结果**:
- `accounting_period.status = 'CLOSED'`
- 关账后任何新建 JE 以该期间为目标时 → 期望 55000 错误

**边界条件验证**: 关账后创建凭证 → 期望 423（期间锁定）

**禁止操作**:
- 不得在未完成银行对账的情况下关账
- 不得关闭有未处理 WBS 积压的期间

**证据**: 关账 API 响应截图；关账后凭证创建的 423 响应截图

**签核位（财务主管）**: _________________ 日期: _________

## 第五步：财务报表

**执行者**: 财务分析师（`GL.REPORT.VIEW` 权限）
**操作**: 读取当期财务报表

**预期结果**:
- 资产负债表（BS）：左右平衡（资产 = 负债 + 权益）
- 损益表（P&L）：科目 610000 借方 1,000.00 USD
- 报表内容与 ledger_line 手工汇总一致

**禁止操作**: 不得将报表数字直接作为财务申报数据（UAT 数据）

**证据**: 报表截图；与 ledger_line 直接查询对比验证

**签核位（财务分析师）**: _________________ 日期: _________
